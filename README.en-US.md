## Docker Command Instructions

* Start an already created container: `docker start <container_name>`
* Stop a started container: `docker stop <container_name>`
* Restart a stopped or starting container: `docker restart <container_name>`
* View container logs: `docker logs -f --tail 100 <container_name>`
* Enter the container's bash command line: `docker exec -ti <container_name> bash`

## Docker-Compose Command Instructions

> The directory where the command is executed must contain a `docker-compose.yml` file.

* Start the orchestrated containers: `docker-compose up -d`
* Stop and remove the orchestrated containers: `docker-compose down`

## RabbitMQ

### Start

Navigate to the `rabbit` folder under the `compose` directory.

The folder contains a `docker-compose.yml` file.

Use `docker-compose up -d` to start it in the background.

> In the docker-compose file, volumes:
>
> - `../../conf/rabbit/plugins:/plugins/my`: Map the image's `/plugins/my` directory as a custom plugin directory.
>
> - `enabled_plugins`: Manage the list of default startup plugins. If you need to add a new default startup plugin, simply add the name in the file, e.g., `[rabbitmq_management, rabbitmq_delayed_message_exchange]`.

### RabbitMQ Plugin Usage

* After starting the Docker container, execute the following commands to enable or disable the `rabbitmq_delayed_message_exchange` plugin:

  > Enable command: `docker exec rabbit sh -c "rabbitmq-plugins enable rabbitmq_delayed_message_exchange"`
  >
  > Disable command: `docker exec rabbit sh -c "rabbitmq-plugins disable rabbitmq_delayed_message_exchange"`
  >
  > View plugin list: `docker exec rabbit sh -c "rabbitmq-plugins list"`

#### Spring Boot Usage

* Add the following dependency to `pom.xml`:

  ```xml
  <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-amqp</artifactId>
  </dependency>
  ```

* Code implementation:

  * Queue creation:

    ```java
    import org.springframework.amqp.core.*;
    import org.springframework.context.annotation.Bean;
    import org.springframework.stereotype.Component;

    import java.util.HashMap;
    import java.util.Map;

    @Component
    public class RabbitMQConfig {

        public static final String MQ_QUEUE_NAME = "QU_SHI";
        public static final String MQ_EXCHANGE_NAME = MQ_QUEUE_NAME;
        public static final String MQ_ROUTING_KEY = MQ_EXCHANGE_NAME;

        @Bean
        public static Queue queue() {
            return new Queue(MQ_QUEUE_NAME);
        }

        @Bean
        public static CustomExchange exchange() {
            Map<String, Object> arguments = new HashMap<>();
            arguments.put("x-delayed-type", "direct");
            return new CustomExchange(MQ_EXCHANGE_NAME, "x-delayed-message", true, false, arguments);
        }

        @Bean
        Binding bindingExchangeMessages(Queue queue, CustomExchange exchange) {
            return BindingBuilder.bind(queue).to(exchange).with(MQ_ROUTING_KEY).noargs();
        }
    }
    ```

  * Producer and consumer:

    ```java
    import com.trend.config.RabbitMQConfig;
    import org.springframework.amqp.core.AmqpTemplate;
    import org.springframework.amqp.core.Message;
    import org.springframework.amqp.core.MessageProperties;
    import org.springframework.amqp.rabbit.annotation.RabbitListener;
    import org.springframework.beans.factory.annotation.Autowired;
    import org.springframework.stereotype.Component;

    @Component
    public class MqUtil {

        private static AmqpTemplate rabbitTemplate;

        @Autowired
        private void setRabbitTemplate(AmqpTemplate rabbitTemplate) {
            MqUtil.rabbitTemplate = rabbitTemplate;
        }

        public static void send(String msg) {
            send(msg, 0);
        }

        public static void send(String msg, Integer delay) {
            if (delay <= 0) {
                rabbitTemplate.convertAndSend(RabbitMQConfig.MQ_ROUTING_KEY, msg);
            } else {
                MessageProperties properties = new MessageProperties();
                properties.setDelay(delay);
                Message message = new Message(msg.getBytes(), properties);
                rabbitTemplate.send(RabbitMQConfig.MQ_EXCHANGE_NAME, RabbitMQConfig.MQ_ROUTING_KEY, message);
            }
        }

        @RabbitListener(queues = RabbitMQConfig.MQ_QUEUE_NAME)
        private void process(Message message) {
            System.out.println("Message consumed: " + new String(message.getBody()));
        }
    }
    ```

## Kafka

> Hardware affects performance, and the priority considerations are as follows:

* Disk: The most important factor for producers is read and write speed, and you need to consider partitioning (multiple partitions, multiple directories, backup issues).
* Network: Producers and consumers' writing speed and reading speed.
* Memory: Consumer performance (0 copy, producers and consumers all operate in memory).
* CPU: Mainly reflected in compression.

#### Producer

* Instance:

* `bootstrap.servers`: This attribute specifies the list of broker addresses, with the format `host:port`. The list does not need to include all broker addresses; the producer will query other broker information from the given broker. However, at least 2 broker addresses (separated by commas, e.g., `127.0.0.1:9092,192.168.0.13:9092`) need to be provided, so that if one broker is down, the producer can still connect to the cluster.

* `key.serializer`: The producer interface allows parameterized types, which can pass Java objects as keys and values to brokers. However, brokers expect to receive messages with keys and values as byte arrays, so a serializer to convert objects to byte arrays must be provided. `key.serializer` must be set to a class that implements the `org.apache.kafka.common.serialization.Serializer` interface. Kafka's client provides `ByteArraySerializer`, `IntegerSerializer`, `StringSerializer` by default, and you can also implement your own custom serializer.

* `value.serializer`: The same as `key.serializer`.

  See the code in the module `kafka-no-spring` under package `hellokafka`.

##### Sending Methods

* Send and forget: Send without any processing, highest efficiency, has retry mechanism, but may lose messages.

* Synchronous send: Send returns a future object, use `.get()` to get metadata synchronously blocking.

* Asynchronous send: `new Callback(){}`.

* ACK mechanism:

  > Message replication mechanism in the cluster (banks generally use 5 replicas, different racks, disaster recovery in different locations)

  * 0: After sending the message, it's no longer managed.
  * 1: If sent to the leader, if the leader is down, an exception will be thrown (with retry). **Default**.
  * -1:
  * all: All partitions must be successfully written before success is returned.

## MySQL Multi-Master Setup (Three Masters, More Masters Operate the Same)

### Operations that Master Containers Need to Perform

Refer to the document [Using Docker to Build Dual-Master MySQL](https://www.cnblogs.com/huangqingshi/p/12593395.html?spm=a2c4e.10696291.0.0.752b19a4bq5Cii)

> Based on `/docker/compose/mysql-ha/docker-compose.yml`

One slave cannot synchronize with multiple masters. So if there are three MySQL, the synchronization relationship is: 2 synchronizes with 1, 3 synchronizes with 2, 1 synchronizes with 3 (ring-shaped).

When configuring, please sort out the synchronization relationship clearly.

Master-slave configuration is simple: just need to configure a slave, 2 synchronizes with 1, others don't need operation. For setting read-only, please search the document yourself.

```shell
# Enter the container
docker exec -ti mysql_master1 bash

# Login to MySQL
mysql -uroot -proot

# Open permissions
GRANT REPLICATION SLAVE, REPLICATION CLIENT ON *.* TO 'root'@'%';

# View the master log file and position
show master status;
```

### Operations that Slave Containers Need to Perform

```shell
# Configure synchronization
# master_host: target host address
# master_port: target host port
# master_user, master_password: target host username and password
# master_log_file, master_log_pos: information obtained from `show master status;`
change master to master_host='mysql_master2',master_port=3306, master_user='root',master_password='root',master_log_file='mysql-bin.000003',master_log_pos=395;

# Start the synchronization thread
start slave;

# Check if it's successful. If successful, it will display:
# Slave_IO_Running: Yes  # If it's NO, check network or account password port
# Slave_SQL_Running: Yes
show slave status \G;

# Stop synchronization
# stop slave;
```
